# LongHorn v0.1 delivery plan

This records the agreed product direction: continue the existing modular
architecture until developers can run and use one complete LongHorn workflow.
Every implemented feature gets its own Markdown guide, connected through the
[feature index](features.md) and [architecture](architecture.md).

## 1. Account command history — implemented

Members can browse earlier commands and delivery status after restarting without
retaining every command ID. Pages are bounded, owner-scoped and cursor-based;
operators have an explicit deployment-wide view. Existing commands survive schema
upgrade, and unavailable/pruned delivery metadata stays distinguishable from success.
[Native evidence](command-history-testing.md) covers permissions, upgrade,
concurrent writes and restart. [History API](account-command-history.md) records
the live-pagination and unavailable-metadata boundaries.

## 2. Web console — implemented

A working browser flow connects signup/sign-in, command creation/history,
command/receipt detail and operator inspection, retry and audit history. Screens
use the real APIs and account policy, with useful loading, empty and failure states.
Verify accessibility and real screenshots before reporting screens complete.
[Console guide](web-console.md), [security](console-security.md),
[recovery](console-recovery.md) and [native verification](console-testing.md)
record the implemented flow and the real-device accessibility boundary.

## 3. One complete example application — implemented

Package the existing command/receipt workflow as a coherent example that developers
can run, inspect and adapt. Explain how account policy, DI, transactions,
idempotency, delivery and audit connect. The example must work through its actual
user flow, including receiver outage and recovery, rather than rely on fixtures
or seeded response data.
The [complete walkthrough](command-application.md) connects the working browser,
temporary native demo and persistent host. The browser/native gates verify actual
computed receipts, outage/recovery, ownership and attributed audits.

## 4. Setup and deployment — implemented

Provide a persistent starter/setup path with explicit runtime configuration,
schema deployment, operator provisioning, receiver storage and production ingress
settings. A new developer should be able to follow the documented steps without
reading this conversation. Keep owner/provisioning credentials separate from HTTP.
Verify the generated or packaged artifact independently of the workspace.
The [independent archive](command-app-distribution.md) contains editable source,
receiver, local framework snapshot, [runtime grants](runtime-role-grants.md) and
[deployment instructions](command-app-deployment.md). [Native verification](command-app-testing.md)
installs/builds it after relocation, deploys its actual schema/grants and uses its
browser/receiver workflow across outage and both processes restarting.

## 5. Release hardening — implemented with hosted review gates

Run permission and input-boundary checks, verify backup/restore of retained state,
add repeatable CI gates and document schema/configuration upgrades. Record the
supported runtime/deployment matrix and remaining limitations. A v0.1 release
requires evidence for the complete workflow and documentation, not only exported
package names or passing unit tests.
[Offline backup/restore](command-app-backup.md) proves retained state and a new
computed command in replacement database/storage. Runtime authority and input
denial are exercised by the native gate. [Upgrades](command-app-upgrades.md),
[support matrix](supported-runtimes.md) and [CI configuration](release-verification.md)
record the procedures and evidence. [Locked dependencies](command-app-dependencies.md)
fix each produced application's install graph, and [CI artifacts](ci-review-artifacts.md)
retain review outputs. The implementation is on a tracked review branch in
[draft PR #1](https://github.com/MirHamzaHasan/longhorn/pull/1). Its current hosted
checks/job logs are the authority for that source revision; review the complete
run and independent archive before release. No tagged/published release, merge
or cloud deployment is claimed.

Additional providers and transports remain later integrations in the
[roadmap](roadmap.md). This plan does not mark the overall product complete at
an intermediate feature milestone.

## Account security controls implemented

The [password API](password-change-http.md), [Account page](console-account.md) and
[session controls](session-controls.md) now connect native/generated applications
and the operator console. Each capability has its own policy, native SQL, HTTP,
browser and verification guide in the [feature index](features.md). Scoped sign-out
keeps the current browser or ends all current live sessions with transaction-owned
reauthentication. This records another working milestone, not a release/completion
claim; exact hosted review gates and remaining manual checks still apply.

## Saved command reuse implemented

[Run again](command-rerun.md) adds source-linked review and a fresh command/receipt
through the existing protected APIs. [Displayed account checks](console-viewer-binding.md)
prevent stale cookie-switched tabs from acting under a different identity.
[Native verification](command-rerun-testing.md) covers real results, manual replay,
privacy, loading/navigation and restored independent application behavior.

## Delivery status history filters implemented

[Live filters](history-status-filters.md) now connect existing account history to
native labelled [browser controls](console-history-filters.md), status-bound
[cursor context](history-filter-cursors.md) and appended [index deployment](history-filter-migrations.md).
[Verification](history-filter-testing.md) covers actual queue transitions, scope,
rollback/concurrent upgrade, saved int64 cursors, default-planner index use,
117 command captures and the independently restored application. This remains
another working milestone under the exact revision's hosted review checks.

## Command detail updates implemented

[Bounded delivery/receipt reads](command-live-updates.md) now bring actual receipts
into the existing detail page without repeated manual refresh. A page-owned
[controller](command-follow-lifecycle.md) pauses hidden/offline work, fences canceled
responses and enforces cycle/time limits. [Controls](console-command-follow.md)
preserve focus and offer explicit pause/resume/retry. [Native proof](command-follow-testing.md)
covers real results, error/auth/navigation boundaries, 26 additional browser captures
and the independent archive. This adds no mutation endpoint, schema or grant.

## Selected command metadata export implemented

[History export](history-export.md) now downloads the complete selected traversal
through explicit bounded [NDJSON segments](history-export-format.md). Existing
admission and [page lifetime](history-export-lifecycle.md) govern every read;
[cancel/continue controls](console-history-export.md) preserve focus and scope.
[Native verification](history-export-testing.md) covers actual files, 10000-row
continuation, changed authorization, 34 captures and restored independent assets.
This metadata feature does not replace offline state backup or claim a snapshot.

## Bookmarkable history views implemented

[History view links](history-view-links.md) preserve selected scope/status through
reload and browser [Back/Forward navigation](console-history-navigation.md).
[Sign-in return](history-view-sign-in.md) retains a validated enum-only destination
through cold login, registration and expiry, with explicit operator denial.
[Native proof](history-view-link-testing.md) covers real ownership, malformed claims,
canceled pagination, export context, 26 captures and restored application behavior.
The browser still keeps loaded cursors/private data out of saved links and storage.

## Command-ID search implemented

[Prefix search](history-id-search.md) now finds saved IDs within existing account/
operator/status history. It connects [v3 continuation](history-search-cursors.md),
[owner-deployed expression indexes](history-search-migrations.md), [browser controls](console-history-search.md)
and [searched NDJSON v2](history-search-export.md). [Native proof](history-search-testing.md)
checks actual queue states, retained upgrades, 6000-row plans, query-aware paging,
26 additional captures and restored application search/export. Payload/number text
search and snapshot guarantees remain separate protocols.

## Recovery audit export implemented

[Operator audit downloads](recovery-audit-export.md) now traverse all actions or one
delivery through existing fresh admission. Their [v1 file schema](recovery-audit-export-format.md)
preserves attributed retry snapshots, including all four outcomes and pruned
sources. A [shared bounded collector](bounded-page-export.md) and [page controls](console-audit-export.md)
reuse limits, exact continuation and cancellation with command exports. [Native proof](recovery-audit-export-testing.md)
covers 105 actual recovery requests, real files, role/session/viewer changes,
34 new captures and the independently restored application. Receipt downloads,
snapshot exports and import/restore remain separate protocols.

## Selected computed receipt export implemented

[Computed receipt downloads](receipt-export.md) now cover selected owner/operator/
status/search history and one fresh protected command. Their [v1 format](receipt-export-format.md)
preserves actual results and explicit not-found observations without raw inputs.
[Serial enrichment](receipt-export-lifecycle.md) keeps fresh admission, smaller
1000-command/ten-page bounds and whole-page continuation. [Controls](console-receipt-export.md)
cancel on changed contents and share page disposal with follow. [Native proof](receipt-export-testing.md)
covers actual broker effects, 1002 HTTP writes, exact retained continuation,
46 captures and restored standalone downloads. Snapshot export, import/restore
and further provider integrations remain separate work.

## Account-owned named history views implemented

[Named views](saved-history-views.md) now persist personal scope/status/search across
sessions and host restart. [Shared values](saved-view-values.md) feed [owner-only CRUD](saved-view-http.md),
[transaction/revision ownership](saved-view-concurrency.md), the appended [005 schema/grants](saved-view-migrations.md)
and the [native browser panel](console-saved-views.md). [Proof](saved-view-testing.md)
covers concurrent quota/edit races, real interrupted commits, changed sessions/roles,
54 new captures and the independently restored application. Sharing/team views,
public short links and further account-retention maintenance remain separate work.


## Opt-in expired request cleanup implemented

[Owned cleanup](idempotency-cleanup.md) now runs serial bounded batches through the
existing store/clock. [Shutdown](idempotency-cleanup-lifecycle.md) drains active SQL
and error observation before pool release. [Default-off host flags](request-cleanup-host.md)
reuse current ledger grants/readiness with no migration. [Retention](request-cleanup-retention.md)
remains logical and table-wide; live replies, business records and saved preferences
retain their existing policy. [Native proof](request-cleanup-testing.md) covers real
Node/Bun/Deno SQLite, restricted PostgreSQL, grant recovery, held replacements,
blocked shutdown and opt-in cleanup in the independently restored archive.
Business-data retention, cluster-wide scheduling and provider integrations remain
separate work.


## Complete command application CLI profile implemented

[command-app generation](command-project.md) now creates the full Node/PostgreSQL
console and separate receipt receiver through both existing CLI entrypoints. The
[shared checked snapshot](command-project-snapshot.md) also owns archive creation,
including actual source/tests, deployment/backup tools and feature guides. Creation
keeps database/receiver setup explicit; installation resolves the initial graph.
[Host script ownership](command-project-lifecycle.md) preserves direct native drain
and custom/hook pnpm behavior. [Packed verification](command-project-testing.md)
uses relocated installed packages and the complete actual SQL/browser/restore flow.
[Source-aware development](command-source-development.md) is now implemented below.
Automatic framework upgrades remain separate work.


## Command and receiver source development implemented

The [command source loop](command-source-development.md) now builds actual app and
console source together, reloads private profiles and preserves running output on
compile failure. [One build sequence](command-development-builds.md) fences latest
edits around [native close](command-development-lifecycle.md). A separate
[receiver watcher](receiver-source-development.md) retains its own storage/output.
[Installed proof](command-development-testing.md) covers real recursive edits,
SQL/HTTP held through reload, latest generations, replay/session/receipt persistence,
config failure, terminal cleanup and a forced stop reported as failure. Automatic
framework upgrades and multi-host orchestration remain separate work.


## Read-only operator preflight implemented

[Runtime checks](operator-preflight.md) now diagnose configuration, built assets,
PostgreSQL/schema/access, restricted role and protected receiver before serving.
[Report v1](operator-preflight-report.md) carries fixed private-safe observations.
[Shared readiness](postgres-application-readiness.md) keeps live startup/probes aligned;
[owned interruption](operator-preflight-lifecycle.md) drains admitted work and close.
[Native proof](operator-preflight-testing.md) covers actual archive/installed CLI,
failure/recovery, interrupted SQL and unchanged pending/expired/business state,
then checks the restored app. Owner migration checksums, exhaustive mutation grants,
production ingress and automated repair remain separate verification/actions.


## Request attempt limits implemented

[Portable budgets](request-limits.md) now connect [bounded memory](rate-limit-memory.md),
[managed SQLite/PostgreSQL](rate-limit-sql.md) and explicit [Hono routes](rate-limit-http.md).
[Owned drain](rate-limit-lifecycle.md) precedes borrowed database close. The
[default-off command policy](command-request-limits.md) shares accounts across
sessions/hosts and connects migrations/grants, startup/readiness/preflight and
retained backup state. [Native proof](rate-limit-testing.md) covers actual runtimes,
SQL contention, process death, upgrade races, HTTP denial and restored distributions.
Rolling/token-bucket algorithms remain separate work. Redis, D1, Durable Object
storage and explicitly owned bucket cleanup are implemented below.


## Redis request attempt storage implemented

[Redis budgets](redis-rate-limits.md) now use explicit [server-owned time](rate-limit-server-clock.md)
and one native script, while the existing memory/SQL clock callbacks stay valid.
[Deployment](redis-rate-limit-deployment.md) records noeviction, minimal ACL and
retained-state requirements. [Ownership](redis-rate-limit-lifecycle.md) drains a
borrowed connection through ambiguous post-commit failure without automatic retry.
A [protected API example](redis-rate-limit-example.md) computes real reports across
hosts and token rotation. [Native proof](redis-rate-limit-testing.md) covers actual
Redis contention/TTL/ACL, killed AOF recovery, HTTP outage and lost-reply shutdown;
other runtimes run the portable protocol with an explicit fake command client.
Redis cluster/failover and native Redis transports outside Node remain separate work.


## Native D1 request budgets implemented

[Atomic SQLite batch limits](batch-rate-limits.md) now supply the existing server-time
port through one native UPSERT/RETURNING. The [optional public task policy](d1-request-limits.md)
connects validation/replay, [appended schema](d1-limit-schema.md), complete deployment
verification and [HTTP/native drain](d1-limit-lifecycle.md). [Native proof](d1-limit-testing.md)
covers real D1 time, rollback/lost acknowledgement, bounded pruning, owner upgrade
races, two-worker quotas and packed/relocated CLI hosts with retained budgets.
Distributed edge deployment and platform-owned maintenance remain separate work.


## Durable Object request budgets implemented

[Object budgets](object-request-limits.md) reuse the existing managed SQLite store
and post-ownership application clock. The [default-off report policy](object-report-limits.md)
shares direct and scheduled submissions in each fixed Object owner. [Complete
schema profiles](object-limit-deployment.md) append after both original scheduled
and alarm histories. [Owned drain](object-limit-lifecycle.md) preserves borrowed
storage and existing wakeup planning; exhausted HTTP budgets do not stop reports.
[Native proof](object-limit-testing.md) covers forty competing clients, actor abort
before/after commit, workerd retention, failed upgrades, automatic results and
actual shipped hosts through disable/re-enable and live policy mismatch.
Cross-Object/global quotas, distributed edge deployment and platform-owned
maintenance remain separate work.


## Owned request-budget cleanup implemented

[RateLimitCleanup](rate-limit-cleanup.md) now schedules explicit serial bounded
pruning through the limiter's existing clock/store. One shared [PruneWorker](prune-worker.md)
also owns the compatible idempotency cleanup facade. [Shutdown](rate-limit-cleanup-lifecycle.md)
drains admitted native work/observation before limiter/database release.
[Retention and authority](rate-limit-cleanup-retention.md) preserve live budgets and
separate PostgreSQL maintenance credentials. A [runnable SQLite report API](rate-limit-cleanup-example.md)
keeps cleanup default-off and validates settings before acquisition. [Proof](rate-limit-cleanup-testing.md)
covers native Node/Bun/Deno SQLite, restricted PostgreSQL renewal/permissions/locks,
finite workerd and independently packed/relocated exports and declarations.
Persistent Workers maintenance remains a separate application integration.
A dedicated command application maintenance process is implemented below; no
global leader or HTTP runtime grant is installed.


## Separate command budget maintenance implemented

[Native check/once/watch](command-limit-maintenance.md) now ships in the command
application and its CLI/archive profiles. [Transactional role provisioning](command-limit-maintenance-role.md)
keeps DELETE in a separate restricted identity. Read-only schema/authority checks
precede pruning; [managed interruption](command-limit-maintenance-lifecycle.md)
drains actual SQL and [private v1 reports](command-limit-maintenance-report.md)
preserve acknowledged counts. [Proof](command-limit-maintenance-testing.md) covers
role/schema denial, concurrent processes, actual account expiry/replay, blocked
signals, grant recovery and independently installed archive/packed-CLI commands.
The HTTP host acquires no maintenance identity or timer. External scheduling and
persistent Workers maintenance remain separate application deployment choices.


## Active-session inventory implemented

[Optional inventory](session-inventory.md) now lists bounded live sessions and ends
one selected sign-in. [Cursors](session-inventory-cursors.md) bind account and
initiating public reference. [Appended native references](session-inventory-schema.md)
leave old login/password writers and AuthStore/SessionManager contracts unchanged.
[SQLite](sqlite-session-inventory.md) and [PostgreSQL](postgres-session-inventory.md)
reauthenticate/sample time under ownership; [HTTP](session-inventory-http.md) keeps
existing body/origin/viewer guards and current-cookie clearing. The [Account panel](console-session-inventory.md)
adds real expiry/current rows with [owned lifecycle](session-inventory-lifecycle.md).
[Proof](session-inventory-testing.md) covers native engines, Object SQL, commit death,
real browser interactions and independently restored application references.
Device/IP/creation metadata, credential recovery/reset and MFA remain separate work.
